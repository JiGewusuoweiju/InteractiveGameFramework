# 验收清单

## M0 骨架
- 根目录九个指定文件与七个核心目录齐全。
- `npm run check` 成功，示例引用与 Schema 一致。
- 健康检查返回 skeleton，未实现接口返回 404。
- 不包含真实密钥、大视频、node_modules 或伪造 Cocos 工程。

## M1 Runtime
- 真实视频播放完毕后出现选择；至少两条结果不同的测试路径证明条件过滤与赋值符合配置。
- 正常、失败重试、无可用选择、结局均有可观察结果。
- 本机存档按 gameId/releaseVersion 隔离，重启后恢复；不宣称已有账号或跨设备同步。

## M2 抖音可行性
- 记录实际设备、系统、Creator/SDK 版本、播放/加载耗时和内存观察。
- 真机验证远程视频、弱网/加载失败恢复与前后台切换；不将正式 Server API 算作已验证。

## M3/M4 首款游戏
- 正式剧情的范围和素材使用权已确认；实际内容与技术 demo-game 区分。
- 全部预期路径在真机可玩，配置与素材版本可追溯；验证本机旧档面对新版本的行为。
- 首版配置/视频分发方案经过真机验证，发布失败有可执行的回退方式。
- 核对上线时的平台要求并记录实际上线结果；不能仅以本地构建成功代替上线验收。

## M5/M6 后台与服务闭环
- 创建两个游戏，各自素材和草稿隔离。
- 上传视频、画布连线、变量条件、预览、发布后 Runtime 可消费。
- 拒绝未授权写入、跨游戏资源、悬空引用、类型错误与过期 revision。
- 发布失败不影响正式版本；重试不重复发布；旧存档不会自动切换版本。

跨设备存档不在首款游戏或 M5/M6 的默认验收范围；若决定实现，另补身份与旧档迁移验收。
